# 1. Relation як first-class entity
Так, 100%.

Бо інакше зв'язки будуть тупими стрілками.

Погано:

```
React ---- USED_IN ---- Project
```
Бо втрачається контекст.

Краще:

```
Relation: UsedIn

from:
Skill React

to:
Project SeaRates

metadata:

role:
Primary technology

period:
2021-2025

depth:
Production

impact:
Architecture ownership
```
Тобто relation теж має:

- тип;
- властивості;
- provenance;
- history.
Фактично:

```
Entity
+
Relation
+
Event
```
усі рівноправні громадяни графа.

# 2. Event як first-class entity
Так.

І тут дуже красиво сходиться з DTJ.

Бо ми отримуємо:

## DTJ

> Що робив агент/система?

## Graph Event

> Що змінило модель світу?
Приклад:

DTJ:

```
Agent asked:
"Скільки користувачів було?"

User answered:
"100k"

Tool processed:
added evidence
```
Graph:

```
Event:

EvidenceAdded

Entity:
Project SeaRates

Data:
100000 users

Source:
MCP Interview
```

# 3. Derived Nodes
Оце реально цікаве питання.

Я думаю — **так, але окремим типом**.

Не змішувати факт і висновок.

Наприклад:

Факти:

```
Project A
Project B
Project C

Skills:
React
Architecture
Performance
```
Derived:

```
Pattern:

"Frontend architecture specialization"
```
Але:

```
type:
DerivedInsight

confidence:
0.87

generated_by:
Analysis Engine
```
Тобто система каже:

> Це не факт. Це висновок.
Це дуже важливо для довіри.

# 4. Deterministic Runtime
Тут однозначно.

Core повинен бути детермінованим.

Однаковий граф:

```
Input A
+
Input B
```
має дати:

```
Output X
```
Інакше неможливо:

- дебажити;
- версіонувати;
- мігрувати;
- тестувати.
AI randomness має бути зовні:

```
AI Layer

↓

Proposal

↓

Runtime validates

↓

Event
```

# 5. Три репозиторії
Оце дуже правильне рішення.

Я б навіть розділив відповідальність:

---

# 1. Graph Memory Core
Private.

Це твій двигун.

Містить:

- graph storage;
- event engine;
- snapshot engine;
- query engine;
- indexing;
- runtime;
- migration engine.
Не знає:

- career;
- docs;
- assets.

---

# 2. Graph Language Runtime
Тут цікавіше.

Я б зробив окремим.

Він відповідає за:

- parser;
- compiler;
- type checker;
- execution;
- package system.
Типу:

```
.graph

↓

Compiler

↓

Graph IR

↓

Core Runtime
```

---

# 3. CareerGraph
Open source.

Це те, що бачить світ.

Містить:

- UI;
- Career schema;
- MCP tools;
- importers;
- workflows;
- vacancy logic;
- career projections.

```
CareerGraph

як

Linux distribution

Graph Memory Kernel
```
